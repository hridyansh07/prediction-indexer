# Polymarket normalizer v1

`polymarket-normalizer` implements Polymarket as a `VenueAdapter` for the
shared `canonical_normalizer::Normalizer`. It consumes audited Phase 0 records
and emits only the existing closed Replay domain. It does not own a book,
recovery journal, fee calculation, strategy, publisher, or live connection.

## Identity and exactness

- Bundle identity is SHA-256 of
  `prediction-indexer/polymarket-normalizer/v1`. Any semantic change requires a
  version bump.
- The closed config identity contains price scale (default 4), quantity scale
  (default 6), and the additive-field policy (default enabled). Explicit
  defaults hash identically to resolved defaults.
- Venue prices and quantities must be decimal JSON strings. They use
  `ConditionalMarketPrice` and `Qty`/`PositiveQty`; floats, signs, exponents,
  inexact rescaling, overflow, and implicit rounding reject.
- Each token ID is its own `ContractOrientation::Outcome` instrument. The
  normalizer never computes a complement, fee, or synthetic opposite side.
- Polymarket's 40-character state value is `BookStateHash::Sha1(Sha1)`, not
  `Sha256` or an untyped string. This changed the undeployed Replay persisted
  schema from version 2 to 3. Kalshi event meaning is unchanged; its absent hash
  remains `None`.

## Supported capture matrix

| Capture shape | Result | Semantics |
|---|---|---|
| WS `book` | one `BookEvent::Full` | Full initialization for one asset. The retained live shape may omit `hash`; no value is invented. Bids and asks are sorted canonically by the domain. |
| WS `price_change` | one `BookEvent::Delta` per `price_changes[]` child | `BUY` is bid and `SELL` is ask. Positive `size` is an absolute `LevelChange::Set`; zero is `Delete`. Child order is source order. |
| WS `last_trade_price` | one `TradeEvent` | Exact price and positive size; `BUY`/`SELL` maps only to aggressor bid/ask. Transaction ID and fee-rate evidence remain in the source sidecar; no fee is calculated. |
| REST `POST /books` item on `public_snapshot` | one `AuditAnchor` | Independent typed full-state evidence only. It is never a `FullBook` and cannot reset current state. The payload timestamp must equal the snapshot cursor. |
| WS `tick_size_change`, `best_bid_ask`, `new_market`, `market_resolved` | validated `ParseReject` + paired `NormalizationFault` | These can affect future interpretation but the current Replay domain has no truthful event variant. They remain visibly unsupported, never silently ignored. |
| WS unknown `event_type` | `unsupported_message_type` reject/fault | Conservative incomplete-interpretation signal. |
| WS `PONG` | intentional `application_heartbeat` ignore | The exact non-JSON frame remains in the sidecar. Other malformed text rejects as `invalid_json`. |
| splice lifecycle and target controls | typed `ControlEvent` or stable intentional ignore | Connection open/close/failure, subscription changes, and metadata digest changes are typed. Operational notices without a closed domain variant remain sidecar-visible ignores. |
| top-level WS array | flattened in array order | Nested `price_changes[]` children remain adjacent. Any malformed member rejects the complete delivery, so one source is never partly accepted and partly rejected. |

The official AsyncAPI does not close objects against additive fields, and the
official Rust response types are non-exhaustive. V1 therefore accepts additive
members by default while still requiring and exactly typing every known member.
Setting `accept_additive_fields=false` is an explicit identity-changing strict
mode. Process controls remain closed because they are generated by this
repository, not an open vendor schema.

## Hash evidence semantics

The retained 2026-09-04 public sample ran for 600 seconds over 12 markets / 24
assets: 240 REST books and 8,159 WS deliveries. After startup censoring, 216/216
REST `(asset_id, hash)` pairs occurred in WS and had a full-level match; the
official server-compatible SHA-1 reproduced 240/240 REST values.

This is asset-scoped full-state evidence, not delivery certification. Ten REST
observations had two consecutive same-hash WS candidates: the first delivery
differed by one level and the second matched. V1 therefore attaches the typed
hash to every child while preserving every delivery and address. It performs no
grouping, deduplication, state verification, rewind, or recovery. REST repetition
(eight repeated observations, maximum three) likewise remains separate evidence.

Official sources inspected for V1:

- [Market Channel AsyncAPI](https://docs.polymarket.com/api-reference/wss/market)
- [Order-book REST guide](https://docs.polymarket.com/market-data/prices-order-books)
- [`rs-clob-client-v2` WS response types](https://github.com/Polymarket/rs-clob-client-v2/blob/main/src/clob/ws/types/response.rs)
- [server-compatible Rust SHA-1 utility](https://github.com/Polymarket/rs-clob-client-v2/blob/main/src/clob/utilities.rs)
- [server-compatible Python SHA-1 utility](https://github.com/Polymarket/py-clob-client/blob/main/py_clob_client/utilities.py)

The fixtures under `tests/fixtures` are compact retained records from that live
sample (`book`, `price_change`, `last_trade_price`, and REST book) plus the
official `tick_size_change` example. They intentionally preserve decimal
lexemes and observed optionality.

## Remaining live-data gaps

- No `tick_size_change`, `best_bid_ask`, `new_market`, or `market_resolved`
  arrived in the retained ten-minute sample; those contracts are covered from
  official schemas only.
- The sample had one WS epoch and no reconnect, so cross-epoch hash recurrence
  remains unmeasured.
- No non-contiguous WS hash recurrence was observed. A future auditor must not
  infer that it is impossible.
- The full-state SHA-1 commits metadata and lexical decimal spellings as well as
  levels. This adapter stores the typed supplied value but does not claim to
  recompute a delta hash.
